   ├── TaskEmbeddingGaussianPolicy (Actor mit Embedding Layer)
   ├── TaskEmbeddingQNetwork (Critic mit Embedding Layer)
   ├── PerTaskReplayBuffer (unverändert, aber gibt task_ids zurück)
   └── SACAgentEmbedding (Main Agent Klasse)

2. train_metaworld_embeddings.py
   ├── MetaWorldMT10EnvEmbedding (Env ohne One-Hot Augmentation)

   ├── t-SNE Visualisierung

   ├── Distance Matrix

5. TASK_EMBEDDINGS_README.md
   └── Vollständige Dokumentation


Datenfluss:
-----------

Environment:
  obs (39D) + task_id (int) → info dict
  
Agent.act():
  obs (39D), task_id → embedding_layer[task_id] → (16D)
  concat([obs, embedding]) → (55D) → Actor → Action
  
Replay Buffer:
  Speichert: obs (39D), action, reward, next_obs (39D), done, task_id
  Sample: Batch mit task_ids array
  
Agent.update():
  batch['obs'] (39D), batch['task_ids'] → embeddings
  Forward pass mit embeddings
  Backward pass → Gradients für Embeddings
  Optimizer update → Embedding weights ändern sich


Unterschiede zu Original (sac_agent.py):
-----------------------------------------

ONE-HOT (Original):                    EMBEDDING (Neu):
=====================                  ===================
obs_dim = 49 (39 + 10 one-hot)        obs_dim = 39 (pure)
concat([obs, one_hot])                embedding_layer(task_id)
one_hot ist fest (nicht trainiert)    embedding ist trainierbar
Alle Tasks gleich weit entfernt       Ähnliche Tasks nahe beieinander
Skaliert O(n) mit Tasks               Skaliert O(1) - konstante Dim


Wichtige Änderungen im Code:
-----------------------------

1. Environment Wrapper:
   - ENTFERNT: _augment_obs() 
   - Observation Space: 39D statt 49D
   - task_id in info dict (war schon da!)

2. Policy/Critic:
   - NEU: nn.Embedding(num_tasks, embedding_dim)
   - forward(obs, task_id) statt forward(obs)
   - Embedding lookup: self.task_embedding(task_id)

3. Replay Buffer:
   - sample_batch() gibt jetzt 'task_ids' zurück
   - Batch shape: task_ids = [batch_size] (int64)

4. Training Loop:
   - task_id = info['task_id'] nach reset/step
   - agent.act(obs, task_id) statt agent.act(obs)
   - Alle network calls: network(obs, task_id)


Hyperparameter:
---------------

embedding_dim:
  - 8:  Minimal (eventuell zu klein für MT10)
  - 16: Default (guter Trade-off) ⭐
  - 32: Mehr Kapazität
  - 64: Maximum (ähnlich zu One-Hot, aber learned)

Faustregel: embedding_dim ≈ sqrt(num_tasks) * 4
  - MT3:  8-16D
  - MT10: 12-24D
  - MT50: 28-48D


Performance-Erwartungen:
------------------------

✅ Sollte MINDESTENS gleich gut sein wie One-Hot
✅ Potentiell BESSER durch Transfer zwischen ähnlichen Tasks
✅ Schnellere Konvergenz möglich
⚠️  Bei zu kleiner embedding_dim: schlechter als One-Hot
⚠️  Braucht eventuell minimal mehr Training Steps


Debugging Tipps:
----------------

1. Embeddings ändern sich nicht:
   → Prüfe batch['task_ids'] im sample_batch()
   → Prüfe dass task_id torch.long ist (nicht float!)

2. Performance schlecht:
   → Erhöhe embedding_dim (16 → 32 → 64)
   → Prüfe ob task_ids korrekt sind (0 bis num_tasks-1)
   
3. Memory Fehler:
   → Embeddings brauchen wenig Memory (10×16 = 160 params)
   → Vermutlich anderes Problem

4. NaN in Loss:
   → Wie bei Original SAC (nicht Embedding-spezifisch)
   → Prüfe Learning Rate, Replay Buffer Size
